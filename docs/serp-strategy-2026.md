# 사람인급 검색 순위 전략 (2026-08-16)

목표: "{회사명} 연봉"류 핵심 검색어에서 사람인·잡코리아·캐치와 1페이지 경쟁.
전제: 그들의 순위는 콘텐츠 품질이 아니라 **도메인 권위**에서 나온다 — 백링크 수만 개
+ 월 수백만 브랜드 검색. 정면 승부(같은 키워드에 더 좋은 글)로는 못 이기고,
**권위를 만드는 기계**를 우리 규모로 복제해야 한다.

## 사람인이 순위를 만드는 실제 기계 (역설계)

1. **설문·데이터 보도자료 → 뉴스 인용 → 백링크**: "추석 상여금 평균 105.9만원(사람인 조사)"
   — 우리 추석 페이지조차 사람인을 인용하고 있다. 이 인용 한 번이 백링크 수십 개.
2. **브랜드 검색량**: "사람인" 월 수백만 검색 = 구글의 최강 신뢰 신호.
3. **1차 데이터 독점**: 채용공고·기업정보 원본 보유.
4. 규모(수백만 페이지)와 내부링크.

→ 1·2는 복제 가능(작게), 3은 우리만의 다른 축으로 대체, 4는 이미 상당히 갖춤(약 2,300페이지(빌드 기준)).

## 기둥 1 — 데이터 리포트 → 인용 백링크 (사람인 플레이북의 미니 버전) ★핵심

우리에게 이미 있는 1차 가공 데이터: **485개사 공시·보도 집계 연봉 DB**, 성과급
실지급률 23개사, 업종 28개 집계, 시즌 계산 데이터.

실행:
- 분기 1회 **"머니샐러리 데이터 리포트"** 페이지 발행 — 예:
  - "485개사 데이터로 본 2026 업종별 신입 초봉 순위" (industriesData 집계 재가공)
  - "대기업 성과급 실지급률 5년 추이 — 삼성 OPI vs 하이닉스 PS" (성과급 DB)
  - "2027 공무원 vs 대기업 신입 실수령 비교" (봉급표+계산기 결합 — 우리만 가능)
- 리포트 하단에 **"출처 표기 시 자유 인용" + 인용문 복사 버튼** ("머니샐러리 분석에 따르면…")
  — 기자·블로거의 인용 마찰 제거. CopyAttribution이 출처 링크 자동 첨부(기배포).
- 발행 즉시: 네이버 블로그 요약판 + IndexNow 자동 핑.
- 성공 지표: GSC 백링크 리포트(운영자 콘솔)·referral 유입.

## 기둥 2 — 우리만의 데이터 축 (사람인이 못 따라오는 것)

사람인의 약점 = **계산이 없다**. 평균 연봉은 있어도 "그래서 통장에 얼마?"가 없다.
- 회사 페이지의 실수령·직급·성과급 결합 강화(기구축) — 리포트에서 이 각도만 침.
- careerLevels 확대: 권위 데이터 확보되는 회사부터(금융권 호봉·공기업 알리오 공시 —
  추정 금지 원칙 유지).
- 성과급 시즌 24h 대응(플레이북 1월) — 뉴스보다 빠른 "계산 가능한" 페이지.

## 기둥 3 — 브랜드 검색량 키우기

현재 "머니샐러리" 3개월 197클릭 → 이 수치 자체가 성장 신호로 작동 중.
- 네이버 블로그(원고 7편 재고) 발행 시 **항상 "머니샐러리"를 본문에 브랜드로 표기**
  → 네이버에서 브랜드 인지 → 구글 브랜드 검색으로 환류.
- 공유 시스템(카톡·재현 링크)의 모든 공유 카드에 브랜드 노출(기배포).
- PWA·즐겨찾기 재방문(기배포) = 직접 유입 신호.

## 기둥 4 — 임베드 위젯 (백링크 자동 생산기, 코드 1회 투자)

"내 블로그에 연봉 계산기 달기" — iframe 임베드 위젯 + 복사 버튼 안내 페이지.
블로거가 붙일 때마다 dofollow 링크 + 브랜드 노출. 티스토리·워드프레스 재테크
블로그가 타깃. (구현: /widget/salary iframe 라우트 + /embed 안내 페이지 —
X-Frame-Options SAMEORIGIN 예외 필요 주의, 광고 없는 경량판으로 정책 리스크 0)

## 기둥 5 — 이미 돌고 있는 것들 (유지·강화)

- 기술 SEO: IndexNow(가동 확인), sitemap ~1,800 URL(2026-08-23 실측 정정 — DART lite 219·가이드 허브 7 포함), 구조화 데이터 최대치 — 완료.
- GSC 저격 격주 라운드(Round 1 완료, 28일 창 규율) — 롱테일은 이미 이기는 게임.
- 시즌 선점(추석·공무원 기배포, 캘린더 연중).

## 하지 말 것

- 헤드 키워드("연봉계산기" 90위) 정면 승부 — 권위 쌓이기 전 낭비.

# 실행 플레이북 (2026-08-17 심화 — 기둥 1·4 구현 완료 기준)

## 구현 현황

- **/insights** 데이터 리포트 섹션 신설 (기둥 1). `/report`는 개인용 noindex 페이지가
  선점하고 있어 `/insights` 사용 — 오타 유입 위험 있는 `/reports`는 의도적으로 배제.
- 리포트 1호 `/insights/entry-salary-by-industry-2026` — 순위·수치는 전부 빌드 시
  자체 DB에서 집계(하드코딩 0). 실서비스 회사 수는 **430개사**(485는 중복 제거 전
  원시 수치 — 리포트·노출 텍스트에 485 쓰지 말 것), 국내 집계 대상 401개사.
  ※ 문서 수치는 참고용 — 빌드 자동 집계(site-metrics·entrySalaryReport)가 정본.
- `CitationCopyButton` — 인용문 + "출처: 머니샐러리 데이터 리포트 (URL)" 복사,
  GA4 `citation_copy` 이벤트. (전역 CopyAttribution은 드래그 복사 전용 —
  clipboard.writeText에는 발동하지 않아 버튼이 출처를 직접 내장)
- `reportsRegistry`(src/data/reportsRegistry.ts) = 발행 목록 단일 소스 →
  sitemap 자동 등재 → postbuild IndexNow 전량 자동 핑.
- OG: `/api/og?type=report` + `path=/insights` 자동 분기. 공유 헤딩 `report` 키.
- **/widget/salary** (기둥 4) — edge Route Handler가 광고·GA·카카오 스크립트가
  전혀 없는 자가완결 HTML 서빙(iframe 내 AdSense 실행 = 정책 리스크 → 원천 차단).
  iframe 허용 헤더(CSP frame-ancestors *)는 **핸들러가 응답에 직접 세팅**이 정본 —
  next-on-pages는 next.config headers()를 정적 라우트에 안 내보내는 실측(2026-08-16)
  때문. next.config의 /widget/:path* 규칙은 dev 패리티용(동일 값).
- **/embed** 안내 페이지 — 스니펫의 **크레딧 `<a>` 링크가 백링크 본체**
  (iframe 자체는 링크 주스 0). "크레딧 링크 유지 = 무료 이용 조건"으로 명시.

## 리포트 발행 파이프라인 (2호부터 이 순서대로)

1. **데이터 소스 선정 + 신뢰 등급 표기** — 자체 DB(추정 포함) / 금감원 공시(43개사,
   `disclosed` 필드) / 정부 통계(jobsData `officialStats` 54종). 리포트 방법론
   섹션에 등급 명시 필수 — 명시 없이는 발행 금지(인용 역풍 방지).
2. **집계 검증** — 대표 수치 3개 이상 수기 재검산 (스크래치 node 스크립트).
3. **페이지 골격 체크리스트** — force-static · ASCII 슬러그(한글 슬러그 프리렌더
   404) · datasetLd+articleLd+faqLd+breadcrumbLd · CitationCopyButton 2개 이상 ·
   방법론 섹션 · FAQ 4문 이상 · 크로스링크(기존 랭킹 페이지와 상호보완 명시) ·
   광고는 기존 컴포넌트를 본문 사이 배치(신규 UI는 항상 광고 아래).
4. **등재** — reportsRegistry에 추가(+updatedDate) → sitemap·인덱스 자동 반영.

## 위젯 운영 메모

- 스니펫 구조: iframe + 크레딧 앵커(`utm_source=embed&utm_medium=widget`).
  위젯 내부 하단 브랜드 링크는 `utm_source=widget` — 유입 채널 구분.
- 위젯은 robots Disallow(`/widget/`) + X-Robots-Tag noindex. /embed는 색인 대상.
- 배포 후 프로덕션 `www.moneysalary.com/widget/salary` 응답 헤더 실측 필수
  (`content-security-policy: ... frame-ancestors *`). 실측 결과: ✅ 2026-08-17
  200 OK + 핸들러 CSP(frame-ancestors * 포함)·x-robots-tag noindex·캐시 헤더
  전부 정상. 예측대로 next.config headers()분(XFO 등)은 프로덕션에 미방출 —
  핸들러 직접 세팅이 정본이라는 설계 확정.
- 티스토리 실붙임 테스트: 운영자 티스토리 테스트 포스트에 HTML 모드로 스니펫
  삽입 → 계산기 표시 + 크레딧 링크 확인. 결과: (운영자 확인 후 기록)
- 위젯 세법 상수는 `src/lib/calculator.ts` 단일 소스 — 세율 갱신 시 자동 반영,
  별도 관리 불필요. 매년 7월 연금 상한 갱신 시 위젯도 자동 갱신됨.
