# MoneySalary

Next.js 15 and React 19 application. The owner selected existing Cloudflare Pages and a static build for the Free plan on 2026-10-17. A paid Workers subscription is not authorized.

## Local development and QA

Use Node.js 22. Install dependencies with `npm ci`; postinstall verifies the reviewed dependency backports. Run `npm run dev` or `npm run qa:dev`, then use `http://127.0.0.1:3100`. These commands disable advertisements and analytics for QA. Follow [AGENTS.md](AGENTS.md) before any inspection.

- `npm run qa:build` / `npm run qa:start`: isolated Next QA output in `.next-qa`.
- `npm run qa:pages:build` / `npm run qa:pages:verify`: native static export and Pages package in `.pages-qa`, with ads and analytics disabled and source/output identity checks.
- `npm run qa:pages:start`: verified local Pages runtime on `127.0.0.1:3320`; `-- --port 3000` selects the CI port. External Worker fetches are denied and remote database/secret bindings are absent.
- `npm run qa:pages:http`: non-rendering route, API, PNG and body-limit checks. `npm run qa:run -- scripts/qa-pages-navigation.mjs` checks browser navigation and sharing through the isolated runner. Set `BASE_URL` to the local server for both.
- Legacy OpenNext adapter checks remain available as `qa:cf:build`, `qa:cf:check`, and `qa:cf:start`; these are not the selected publication path.
- `npm run qa:safety`, `npm test`, `npm run lint`: safety, unit and lint checks.

Publisher pages in production or Cloudflare preview must never be opened in a browser for QA. Browser tests require the guarded `qa:run` entry point. QA build directories must never be deployed.

## Production release status and deployment

Publication uses the local approved-release command. GitHub `.github/workflows/ci.yml` verifies pushes and pull requests; it has no `deploy-pages` job. Required repository switches are `PAGES_AUTO_DEPLOY_ENABLED=false` and `PAGES_LOCAL_PUBLISH_ENABLED=true`. Cloudflare's old Git production and preview builds remain disabled. A push or a green QA job alone does not publish anything.

After individual article approval and the normal approval/hash/calendar checks, use the exact approved full commit SHA:

```sh
node scripts/pages-release-local.mjs --approved-commit <full-SHA>
```

The command requires a clean checkout of that exact latest main commit and its successful GitHub `verify` job. It builds and verifies a separate ordinary-visitor `.pages-build` package locally, captures the previous sitemap, uploads once using the existing local Wrangler OAuth login, confirms the canonical deployment and unchanged project configuration, dispatches the existing cache-purge workflow, verifies its receipt, runs 16 bounded non-rendering HTTP contracts, and submits only the IndexNow delta. `.artifacts/pages-release-local/<full-SHA>/` holds the orchestration, deployment, rollback, purge, HTTP and IndexNow receipts. The computer and process must stay running through completion, with a valid local login and GitHub workflow-dispatch access. This change registers no recurring publishing task and does not authorize unapproved articles.

Do not create or store a new Cloudflare API token in GitHub, including `CF_PAGES_API_TOKEN`. The local publisher resolves Wrangler's existing OAuth credential into process memory; it never prints it or writes a credential copy to source, environment files, receipts or logs. The existing GitHub `CF_API_TOKEN` remains only in the `cf-purge` workflow, with Pages Read and Zone Cache Purge permissions. Its `pages-verified-purge` operation checks the exact deployment ID and commit and returns a receipt; that credential is not transferred to the local publisher or Wrangler. The previous plan to add a GitHub Pages Edit token is superseded by this local-login design.

QA builds and browser tests use only `.pages-qa` on localhost with outbound network isolation. Credentials are excluded from installation, build and UI-test children. An existing attempt for the same commit, changed main/configuration, failed purge or ambiguous upload stops publication for operator reconciliation. Do not delete receipts or force a second upload to bypass this protection. Set `PAGES_LOCAL_PUBLISH_ENABLED=false` to stop future approved local releases; keep `PAGES_AUTO_DEPLOY_ENABLED=false` and the obsolete Cloudflare Git build disabled.
