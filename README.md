# MoneySalary

Next.js 15 and React 19 application. The owner selected existing Cloudflare Pages and a static build for the Free plan on 2026-10-17. A paid Workers subscription is not authorized.

## Local development and QA

Use Node.js 22. Install dependencies with `npm ci`; postinstall verifies the reviewed dependency backports. Run `npm run dev` or `npm run qa:dev`, then use `http://127.0.0.1:3100`. These commands disable advertisements and analytics for QA. Follow [AGENTS.md](AGENTS.md) before any inspection.

- `npm run qa:build` / `npm run qa:start`: isolated Next QA output in `.next-qa`.
- `npm run qa:pages:build` / `npm run qa:pages:verify`: native static export and Pages package in `.pages-qa`, with ads and analytics disabled and source/output identity checks.
- `npm run qa:pages:start`: verified local Pages runtime on `127.0.0.1:3320`; `-- --port 3000` selects the CI port. External Worker fetches are denied and remote database/secret bindings are absent.
- `npm run qa:pages:http`: non-rendering route, API, PNG and body-limit checks. `npm run qa:run -- scripts/qa-pages-navigation.mjs` checks browser navigation and sharing through the isolated runner. Set `BASE_URL` to the local server for both.
- Legacy OpenNext adapter checks remain available as `qa:cf:build`, `qa:cf:check`, and `qa:cf:start`; these are not the selected publication path.
- `npm run qa:safety`, `npm test`, `npm run lint`: safety, unit and lint checks.

Publisher pages in production or Cloudflare preview must never be opened in a browser for QA. Browser tests require the guarded `qa:run` entry point. QA build directories must never be deployed.

## Production release status and deployment

Publication uses `.github/workflows/pages-publish.yml` ("Pages · 승인 후 게시"). The repository owner approves an exact full main commit using **Actions → Pages · 승인 후 게시 → Run workflow**. That authenticated manual action is the publication approval; a push or green CI alone never publishes. The approved article publisher can submit the same workflow after the existing chat approval, draft hash, calendar and cap checks.

The cloud workflow verifies that approved SHA is still main and has passed the exact `ci.yml` push/main `verify` job. It then fast-forwards `codex/pages-production` using GitHub's automatically generated job token. Cloudflare's existing GitHub App builds that branch with `node scripts/pages-cloud-build.mjs` and publishes `.pages-build/dist`. Production builds preserve ordinary visitor advertising. QA output is never deployed. The native build independently checks the public approval run and CI records before building.

Cloudflare API tokens and deploy-hook secrets are not used or stored by this pipeline. No custom Cloudflare token is sent to GitHub. The GitHub token is temporary and generated by GitHub per job. Keep `PAGES_CLOUD_PUBLISH_ENABLED=true`, `PAGES_LOCAL_PUBLISH_ENABLED=false`, and `PAGES_AUTO_DEPLOY_ENABLED=false`; Cloudflare production Git builds are enabled only for `codex/pages-production`, with previews disabled. The retired `cf-purge` workflow and local OAuth release remain historical recovery code, not the active publisher.

The workflow captures the previous sitemap, promotes the approved commit, waits for the public native release attestation, checks 16 bounded HTTP contracts and any approved article, then submits only the IndexNow delta. Receipts are uploaded as a GitHub Actions artifact. This verifies publicly observed release identity before and after acceptance; it does not claim a Cloudflare API canonical deployment UUID, account configuration hash or a purge result. Custom mutable HTML/OG cache rules must be disabled so Pages controls cache replacement across deployments. Private response rules and immutable asset caching remain intact.

After dispatch is accepted, the computer may be turned off. The workflow's final success, not dispatch acceptance, means publication completed. A local handoff is available only for an already approved article/commit:

```sh
node scripts/pages-cloud-dispatch.mjs --approved-commit <full-SHA>
```

This reserves a commit-scoped receipt under `.artifacts/pages-cloud-dispatch/<full-SHA>/` and dispatches once. Ambiguous submissions, stale commits, failed QA and an already promoted commit stop; never force a replay or delete receipts to bypass them. Set `PAGES_CLOUD_PUBLISH_ENABLED=false` to stop future publication. This setup creates no recurring writer and grants no approval to future article content. Drafts must already be committed remotely before a phone/browser approval can deploy them while this computer is off.

QA builds and browser tests use only `.pages-qa` on localhost with outbound network isolation. Installation/build children receive an allowlisted environment without credentials. Remote acceptance uses non-rendering HTTP, no document JavaScript, redirects, ad/analytics requests or subresources.
