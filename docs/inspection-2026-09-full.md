## 2. 계산 정확성 (돈이 틀리던 것)

### 2-1. 근로소득세액공제 한도가 법정 산식이 아니었다 — 전 사이트 영향

`taxConstants2026.earnedIncomeTaxCredit2026` 이 각 구간의 **상단 값**(74만·66만·50만)을
상수로 고정하고 총급여 3,300만 이하에는 한도를 두지 않았다. 소득세법 §59② 는
구간 안에서 총급여에 비례해 체감하는 산식이다.

| 총급여 | 구 한도 | 법정 한도 | 과다공제(연) |
|---|---|---|---|
| 3,300만 | 무한도 | 740,000 | 107,000 |
| 5,000만 | 740,000 | 660,000 | 80,000 |
| 8,000만 | 660,000 | 500,000 | 160,000 |
| 1.21억+ | 500,000 | 200,000 | 300,000 |

→ 연봉 4,000만 이상에서 월 3,380~27,500원 실수령 과대. 정정 후 파생 카피
(layout meta·OG·twitter, 홈 FAQ·SEO 섹션, /table/2026 annual·monthly 타일·FAQ,
가이드 실수령표 10행)를 전량 동기화했다. 예) 연봉 5,000만 353만 → **352만**,
1억 650만 → **648만**.

### 2-4. 백그라운드 정독 감사가 추가로 잡은 두 건 (6차)

**연말정산 본편 계산기의 4대보험이 초기값에 얼어 있었다.**
`YearEndTaxCalculator` 가 4대보험 소득공제를 `useState` 초기값(총급여 5,000만 기준)으로
잡아 두고, 총급여를 바꿔도 다시 파생하지 않았다. 화면에 4대보험 입력란이 없어 사용자가
바로잡을 수단도 없었다. 결정세액 실측 오차: 총급여 2억 **+3,356,302원 과대**(환급 과소),
1.2억 +1,700,464원, 3,000만 -126,783원 과소. → 계산 직전에 현재 총급여로 재파생.

**회사 직급별 실수령액 표가 세액공제를 ×0.7 로 근사했다.**
회사 상세 430쪽에 붙는 `CompanySalaryTable` 이 자체 세율표·근로소득공제 사본을 두고
산출세액에 일률 `×0.7` 을 곱해 근로소득세액공제를 흉내 냈으며 비과세 식대도 빼먹었다.
근로소득세액공제는 총급여 구간별 한도(1.2억 초과 20만원)가 있어 고연봉일수록 오차가 커진다 —
사이트 자체 계산기 대비 **연봉 2억 +9.9%, 8억 +21.1% 과다**, 4,000만 -2.0% 과소.
→ `calculateSalary2026` 정본으로 교체하고 인라인 세율표를 제거(`verify:tax` 허용목록 9 → 8개 파일).

## 3. 계산기 UI — 이 사이트의 존재 이유가 깨져 있던 것

1. **소수점 입력 불가** — controlled input 이 파싱된 숫자를 되돌려 `"3."` 이 `"3"` 으로
   복구됐다. 금리 3.5% 를 치면 **35%** 가 확정되고 월 상환액이 143만원 → **875만원**
   (실브라우저 실측). 모바일은 `inputMode="numeric"` 이라 소수점 키조차 없었다.
2. **금액 만 단위 절사** — `formatNumber` 가 1만~1억 구간을 만 단위 정수로 압축해
   환산 시급 **23,974원을 "2만원"**(-16.6%), 주휴수당 82,560원을 "8만원"으로 표시했다.
   금액은 원 단위 정확값 + 억/만 보조 표기로 전환.
3. **/mbti-salary 결과 산출 붕괴** — 축 판정이 `1 >= undefined` (NaN 비교)라
   가능한 32가지 응답 경로가 전부 ISFJ·ISFP 두 유형으로만 수렴했고 그것도 선택과 반대였다.
4. **/lotto 무한 재귀** — 제외 숫자 40개 이상이면 종료 조건 없는 재귀 → 탭 정지 후 스택오버플로.
5. **/fun/asset-allocator 게임 정지** — stale closure 로 루프가 1프레임 만에 멈춰
   60초 내내 화면 정지 + 0점 게임오버.
6. **/fun/tetris 레벨 고정** — 한 번에 10줄을 지워야만 레벨업(불가능) → SPEED_INCREMENT 사문.
7. 인플레이션 계산기 결과 라벨 "20년 후" 하드코딩, 근로소득세 계산기 결과에 월·연 단위 혼재.
8. NaN/Infinity 화면 노출 3곳: `/global`·`/en/salary-converter` "Tax NaN%",
   `/en/flat-tax` "NaN%", `/fun/escape-plan` "Infinity%".

- **가이드 '관련 계산기' 블록 소멸** — CALC_TO_GUIDES 가 참조하는 슬러그 12개가
  카드 레지스트리에 없어 렌더 단계에서 전량 탈락(가이드 3편은 블록 0건).

  같은 원인으로 회사 15곳이 DART 통계 블록을 통째로 잃고 있었다.
- **쿠팡 공정위 고지문이 가이드 334쪽에서 사라졌다** — `CoupangBannerCore` 의 등록
  이펙트 deps 에 인라인 객체(`responsive`)가 들어 있어 부모가 한 번만 리렌더돼도
  (가이드 상세의 `setMounted`) cleanup→setup 이 재실행되며 등록 순서가 뒤집혔고,
  두 배너가 모두 `bannerIndex !== 0` 이 되어 아무도 고지문을 렌더하지 않았다.
  고지문 누락은 표시광고 정책 위반 소지 그 자체다. deps 를 원시값으로 바꾸고,
  고지 노출을 **구독 레지스트리 기반 소유권**으로 판정하도록 재설계했다
  (첫 시도인 "등록 배열 첫 항목" 판정은 렌더 시점이 등록보다 빨라 고지문이 2개 나왔다 —
  실브라우저에서 잡아 7차에서 교체). 가이드·qna·salary-db 전부 **정확히 1개** 확인.
- **`/api/og` 가 robots.txt 로 막혀 있었다** — 전 페이지 `og:image` 와 `Article.image`
  소스인데 `Disallow: /api/` 에 함께 걸려, SERP 썸네일·Discover 카드·리치결과 이미지가
  전부 죽는 경로였다. → `Allow: /api/og`. 같은 맥락에서 `Disallow: /share/` 도 해제했다

## 6. 인프라·안정성

- `/widget/company?id=constructor` 가 안내 카드 대신 **500**(프로토타입 체인 키가
  ID 검증 통과). → `Object.hasOwn` 으로 자기 소유 키만 허용.
- `/table/*?page=abc` → `parseInt` NaN → 빈 표 + 화면에 "NaN" 노출.
- `/api/salary-table?page=-1` → `slice(-200,-100)` 으로 강등돼 **마지막 부근 실데이터**를
  200 으로 응답. `?page=abc` 는 빈 배열을 오류 없이 응답. → 1 이상 정수만 허용.
- 급여명세서 미리보기의 귀속월(2026년 11월분)과 지급일(2025.11.25) 연도가 1년 어긋나
  있었고, 이 DOM 이 html2canvas 로 캡처돼 다운로드 PNG 에도 들어갔다.

### 확인만 하고 남긴 것

- **`permanentRedirect()` + `dynamic="force-static"` 조합의 캐시 재생 결함** —
  `next start` 실측: 첫 요청은 `308 + Location`, 캐시 HIT 재생에서는 **Location 헤더가
  사라진 308**(30KB HTML 바디 동봉)이 나간다. 내부 링크는 전부 고쳤고 알려진 구 URL 15건은
  next.config 리다이렉트로 라우팅 이전 단계에서 처리했지만, 임의의 미존재 슬러그는
  여전히 이 경로를 탄다. 근본 해결은 `/industry/[slug]`·`/job/[slug]`·`/salary-db/[id]` 에
  `dynamicParams = false` 를 주어 404 로 떨어뜨리는 것이다(정상 404 + Worker 렌더 절감).
  다만 "구 URL 을 404 로 보낼지 인덱스로 리다이렉트할지"는 제품 정책이라 운영자 판단으로 남긴다.
- **`/api/salary-table` 은 소비처가 없다.** `runtime = "edge"` 인데 모듈 스코프에서
  4종 그리드(연봉 2,401행 + 월급 2,001행 + 주급·시급)를 매 콜드스타트마다 생성한다.
- **/global·/en/salary-converter 의 해외 세금**이 급여소득공제·표준공제를 빼고 총급여에
  세율을 직접 적용해 일본 기준 세부담이 과대(국가 순위가 뒤집힐 정도). 외국 세제 테이블
  구현이 필요해 이번 범위에서 제외.
- 성과급 계산기의 **월 기본급 → 추정 연봉 배수**가 13(LG엔솔)·17(LG화학)·18(현대차 계열)로
  갈리는데 근거 주석은 LG엔솔에만 있다. 회사별 급여 구조 판단이라 데이터 담당자 확인 필요.

## 8. 개인정보 — 고지와 실제 전송의 불일치

`/privacy` 는 "사용자 입력 데이터(연봉, 부양가족 수 등)는 브라우저 localStorage 에만
저장되며 서버로 전송되지 않습니다"라고 고지한다. 실제로는 두 경로로 나가고 있었다.

- **GA4 계산 완료 이벤트가 연봉·실수령액을 원 단위 그대로 전송**했다
  (`annual_salary: 57,340,000` 같은 값). → `analytics.salaryBand()` 로 **500만원 구간
  라벨**만 보낸다(세그먼트 분석 목적은 유지되고, GA4 맞춤 측정기준 고유값 한도에도 안전).
- **쿠팡 배너 `subId` 가 pathname 을 그대로 담아** `/share/[data]` 에서 연봉이 인코딩된
  base64 조각이 쿠팡 서버로 나갔고, `referrerPolicy="unsafe-url"` 이 전체 URL 까지
  실어 보냈다. → subId 는 `/share` 로만 기록하고 해당 경로에서만 `referrerPolicy` 를
  `origin` 으로 낮춘다(다른 경로의 어트리뷰션은 그대로).
