# MoneySalary: advertisement-free inspection

The owner requires all agent inspections and automated tests to avoid live ad and analytics requests (2026-10-16).

- Never open `moneysalary.com`, `www.moneysalary.com`, Cloudflare preview deployments, or saved production HTML in a browser for QA. This includes CUA, existing tabs, popups, hidden iframes, reload loops, ad previews, and arbitrary browser JavaScript. A `webdriver` check, `?ads=off`, hiding ads, or a domain blocklist alone is not sufficient protection.
- Inspect production documents only with non-rendering HTTP GET/HEAD, manual redirects, and an identifiable `MoneySalary-QA/1.0` User-Agent. Do not fetch ad/analytics endpoints, `/adgk/`, or execute returned JavaScript. Admin report pages in AdSense, GA4, Search Console, Cloudflare, and Naver Search Advisor are permitted; do not follow their links to publisher pages or ad previews.
- Run UI checks only against a loopback server started with `npm run qa:dev`, or built/started with `npm run qa:build` and `npm run qa:start`. QA output is isolated in `.next-qa`; never deploy it. Do not use a production reverse proxy or copied production HTML as the local target.
- For Cloudflare adapter validation, use `npm run qa:cf:build`, `npm run qa:cf:check` (local dry run), and `npm run qa:cf:start`. This builds the same application with ads disabled in the owned `.open-next-qa` staging directory and binds only to loopback. Never deploy its artifacts or run remote preview. Browser checks still require the network-isolated runner below; HTTP checks do not execute JavaScript.
- Browser test code must use `scripts/lib/qa-safety.cjs` before creating any page. It rejects remote targets and blocks external requests, same-origin advertising/analytics proxies, service workers and unsafe redirects. Use `npm run qa:run -- scripts/<approved-script>` for existing maintained tests. Do not replace guards with direct Playwright/CDP connections or disable interception. Follow the current tool's browser-control restrictions as well.
- When a browser tool cannot establish the required network isolation before navigation, skip that UI check and report the limitation. Use static source tests and HTTP checks instead. Do not load real ads to verify that blocking works; use synthetic fixtures and offline unit tests.
- Historical browser scripts under `docs/` and `.artifacts/` are retired. Never remove their safety stops, copy their production navigation code into a new command, or replay historical browser tool inputs. Port a needed scenario into the maintained guarded tests.
- Preserve these restrictions in every related automation, delegated task and worktree. Run `npm run qa:safety` after changing the QA paths or advertising code. Do not claim an untested browser path is protected.

Keep ordinary visitor advertising behavior intact. Test switches can only disable ads and analytics; no test parameter may enable them. Do not click ads or simulate paid impressions.
