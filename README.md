# MoneySalary

Next.js 15 and React 19 application. The owner selected existing Cloudflare Pages and a static build for the Free plan on 2026-10-17. A paid Workers subscription is not authorized.

## Local development and QA

Use Node.js 22. Install dependencies with `npm ci`; postinstall verifies the reviewed dependency backports. Run `npm run dev` or `npm run qa:dev`, then use `http://127.0.0.1:3100`. These commands disable advertisements and analytics for QA. Follow [AGENTS.md](AGENTS.md) before any inspection.

- `npm run qa:build` / `npm run qa:start`: isolated Next QA output in `.next-qa`.
- `npm run qa:pages:build` / `npm run qa:pages:verify`: native static export and Pages package in `.pages-qa`, with ads and analytics disabled and source/output identity checks.
- `npm run qa:pages:start`: verified local Pages runtime on `127.0.0.1:3320`; `-- --port 3000` selects the CI port. External Worker fetches are denied and remote database/secret bindings are absent.
- `npm run qa:pages:http`: non-rendering route, API, PNG and body-limit checks. `npm run qa:run -- scripts/qa-pages-navigation.mjs` checks browser navigation and sharing through the isolated runner. Set `BASE_URL` to the local server for both.
- Legacy OpenNext adapter checks remain available as `qa:cf:build`, `qa:cf:check`, and `qa:cf:start`; these are not the selected publication path.
- `npm run qa:safety`, `npm test`, `npm run lint`: safety, unit and lint checks.

Publisher pages in production or Cloudflare preview must never be opened in a browser for QA. Browser tests require the guarded `qa:run` entry point. QA build directories must never be deployed.

## Production release status and deployment

The current automatic publication path is `.github/workflows/ci.yml`: a main push must pass the complete `verify` job before `deploy-pages` can run. The repository variable `PAGES_AUTO_DEPLOY_ENABLED=true` enables publication. Cloudflare's old Git build stays disabled so there is only one publisher. The deployment job creates and verifies a separate ordinary-visitor `.pages-build` package, captures the previous sitemap, checks the exact latest main commit, uploads once without a Wrangler configuration override, preserves project bindings and settings, confirms actual cache purge, runs 16 bounded non-rendering HTTP contracts, then submits only the IndexNow delta. Its `pages-release-<commit>` Actions artifact holds deployment, rollback and verification receipts. A green QA job alone is not a completed deployment.

GitHub secret `CF_PAGES_API_TOKEN` needs Cloudflare Pages Edit for the site's account; it is used only for Pages publication and deployment-state reads. The existing `CF_API_TOKEN` remains the cache-purge credential (Zone Cache Purge plus Pages Read for its deployment check), passed to the publisher as `CF_PURGE_API_TOKEN` and never to Wrangler. Both credentials are required, with no fallback. The manual `cf-purge` operation `pages-upload-readiness` checks the Pages upload-token endpoint without uploading or deploying; any returned JWT stays in memory and is discarded. A successful project read does not prove upload permission. Failure receipts retain fixed diagnostic categories and numeric API codes, never raw CLI output or tokens.

QA builds and browser tests use only `.pages-qa` on localhost with outbound network isolation. Credentials are supplied only to release/control-plane steps, not installation, build or UI tests. A rerun, existing deployment attempt for the same commit, changed main/configuration, failed purge or ambiguous upload stops publication for operator reconciliation. Do not delete receipts or force a second upload to bypass this protection. Disable the repository variable to stop future automatic releases; never enable the obsolete Cloudflare Git build in parallel.

The HTML and salary Cache Rules ignored origin cache headers; the HTML rule additionally forced a one-day TTL on status 200. Both rules now respect origin cache headers and bypass caching when absent; the HTML status TTL overrides were removed. Rule expressions and browser TTL settings were preserved. After saved-rule readback and an exact-release-checked purge, the same five private URLs each returned `BYPASS` with no Age on two ordinary GETs. Homepage and salary GETs remained cache hits. These observations confirm the repaired behavior for the checked cases, not every future response or cache tier. Preserve this distinction when reviewing cache changes; do not reintroduce origin-ignoring or status-based TTLs over private responses.
